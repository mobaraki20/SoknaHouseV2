# استاندارد پروفایل عمومی اتاق و امکانات — Sokna House

وضعیت: Design Candidate / Wireframe basis
نسخه برنامه: 2.5.9
Schema فعلی: 2.5.5
این سند به‌تنهایی Release یا تغییر Runtime ایجاد نمی‌کند.

## 1. هدف
داده اتاق باید هم برای مدیریت داخلی و هم برای صفحه عمومی انتخاب اتاق قابل استفاده باشد، بدون آن‌که پنل مدیریت یا صفحه مهمان به فهرست شلوغ امکانات تبدیل شود.

## 2. مشخصات ساختاری اتاق
- تعداد تخت دبل
- تعداد تخت سینگل
- حمام و سرویس بهداشتی اختصاصی: بله/خیر
- ظرفیت پایه
- حداکثر ظرفیت
- نحوه خواب نفر اضافه: برای تمام اتاق‌های فعلی سکنا «سرویس خواب سنتی»
- موقعیت اتاق می‌تواند در داده نگهداری شود، اما نمایش عمومی آن پیش‌فرض خاموش است.

## 3. امکانات اتاق
Registry قابل مدیریت و سبک؛ مدیر باید بتواند مورد اضافه کند، نام را ویرایش کند، غیرفعال کند و آن را به اتاق‌ها نسبت دهد.

Registry اولیه:
- یخچال
- سشوار
- کولر اسپلیت
- بخاری

مواردی مانند آینه قدی به‌صورت پیش‌فرض در خلاصه عمومی نمایش داده نمی‌شوند، چون ارزش تصمیم‌گیری کمی دارند.

## 4. امکانات و خدمات سطح اقامتگاه
Registry جدا از امکانات اتاق:
- صبحانه همراه اقامت (فعال در وضعیت فعلی، قابل خاموش/روشن‌کردن)
- وای‌فای رایگان
- حیاط مشترک
- امکان استفاده از کافه

مواردی که وجود ندارند یا برای مهمان قابل استفاده نیستند نباید نمایش داده شوند؛ در وضعیت فعلی پارکینگ و استفاده از آشپزخانه نمایش عمومی ندارند.

## 5. تصاویر
برای هر اتاق:
- یک تصویر Cover
- حدود 5 تا 6 تصویر Gallery
- افزودن/حذف تصویر
- انتخاب Cover
- ترتیب تصاویر

Gallery باید در صفحه عمومی قبل از CTA واتس‌اپ قابل مشاهده باشد.

## 6. اصل Progressive Disclosure عمومی
کارت نتیجه فقط اطلاعات مقایسه‌ای اصلی را نشان می‌دهد:
- نام
- قیمت
- حداکثر ظرفیت
- چیدمان تخت
- حمام اختصاصی/مشترک
- چند امکان کلیدی
- یادداشت سرویس خواب سنتی در صورت وجود ظرفیت اضافه

جزئیات کامل و Gallery پشت «تصاویر و جزئیات» نمایش داده می‌شوند. امکانات مشترک مجموعه یک‌بار و نه روی تک‌تک اتاق‌ها تکرار می‌شوند.

## 7. استاندارد مدیریت Desktop
- Collection اتاق‌ها در ناحیه اصلی
- یک Inspector مشترک برای ویرایش اتاق انتخاب‌شده
- Editor تکراری داخل هر Card ساخته نمی‌شود
- Bulk Pricing مسیر جدا از Single Room Edit دارد
- Bulk: Selection → نوع تغییر → مقدار → Preview per-room → Commit
- نرخ پایه و هزینه نفر اضافه هر دو می‌توانند Bulk شوند، ولی هر عملیات صریحاً یکی را انتخاب می‌کند.

## 8. Mobile
Side Inspector به Layout ثابت Desktop محدود است. روی Mobile ویرایش باید در Surface تک‌ستونه/Sheet یا Flow مناسب موبایل باز شود و Context و Focus از بین نرود.

## 9. Non-goals
- OTA amenity mapping
- Amenity inventory
- Room category/type engine
- Rate plan engine
- CMS عمومی سنگین
- فیلتر امکانات برای مهمان در V1
- موقعیت پیچیده اتاق به‌عنوان داده اجباری عمومی
